Every page is a `.md` or `.mdx` file under `content/`. The path of the file
becomes the URL: `content/guide/cli.mdx` is served at `/guide/cli`.

## Frontmatter

```yaml
---
title: Content               # page heading, sidebar label, <title>
description: Frontmatter.     # subtitle, meta description, feeds, search
icon: FileText                # sidebar icon
order: 3                      # position inside its sidebar section
label: Content                # shorter sidebar label (optional)
draft: false                  # true hides the page from a production build
date: 2026-01-31              # blog lists, RSS and sitemap use this
updated: 2026-01-18           # "Last updated on …" at the bottom of the page
tags: [guide, mdx]
author: Ada Lovelace
image: /cover.svg             # cover on a blog post, and social preview fallback
ogImage: /social/custom.png   # social-only override (optional)
caption: Shown under the cover image on a blog post
toc: false                    # hide "On this page" for this page
sidebar: false                # not a page in the sidebar, not a post in lists
slug: custom-url              # override the URL (keeps the sidebar position)
fullWidth: true               # render without the sidebar and TOC columns
---
```

The page heading comes from `title`, so start your body at `##`.

| Field | Effect |
| --- | --- |
| `title` | Heading, sidebar label, `<title>`, feeds. |
| `description` | Subtitle, meta description, post list, search index. |
| `icon` | Icon next to the sidebar entry, from the curated set. |
| `order` | Sort key inside the section. Lower first; unset last. |
| `label` | Sidebar text, when `title` is too long. |
| `draft` | `true` excludes the page from a production build. Visible in `dev`. |
| `date` | Drives post ordering, RSS and sitemap `lastmod`. |
| `updated` | Shown as "Last updated on …". |
| `tags` | Badges on a post, and tag pages in the owning blog layer. |
| `author` | Name or `{ name, avatar, url }`. |
| `image` | Cover image on a blog post, and the social preview fallback. |
| `ogImage` | Social preview image only; leaves the blog cover unchanged. |
| `caption` | Caption under the cover image. |
| `toc` | `false` hides the table of contents for this page. |
| `sidebar` | `false` keeps it out of the sidebar, lists and feeds. |
| `slug` | Overrides the URL without moving the page in the sidebar. |
| `fullWidth` | Renders without the sidebar and TOC columns. |

## Routing

| File | URL |
| --- | --- |
| `content/index.mdx` | `/` |
| `content/getting-started.mdx` | `/getting-started` |
| `content/guide/index.mdx` | `/guide` |
| `content/guide/cli.mdx` | `/guide/cli` |

<AccordionGroup>
  <Accordion title="What if there is no content/index.mdx?">
    A docs layer points its root at the first page in that layer, the way mkdocs
    copies `index.md`. A blog layer renders a post list at its root instead,
    because a blog home is a list rather than a page.
  </Accordion>
  <Accordion title="How do I keep a page out of the navigation?">
    Set `sidebar: false`. The page is still published at its URL and still
    appears in the sitemap — it is only removed from the sidebar, the post list
    and the feeds.
  </Accordion>
  <Accordion title="Are duplicate routes allowed?">
    No. If two files resolve to the same URL, the build keeps the first and warns
    with both paths.
  </Accordion>
</AccordionGroup>

## Sidebar sections

Top-level directories become labelled sections; nested directories become
collapsible groups. The section label comes from the directory name, and the
directory's `index.mdx` is listed as an ordinary page:

```text
content/guide/index.mdx      →  section "Guide", first item "Overview"
content/guide/advanced/…     →  collapsible "Advanced" inside "Guide"
```

## Headings and the table of contents

`h2`, `h3` and `h4` are collected automatically into the **On this page** panel.
Every heading gets a stable anchor, so `/guide/content#frontmatter` always works.
The outline is computed at compile time and exported from the page module, which
is why the server-rendered panel and the hydrated one are identical.

## Code blocks

Fenced blocks are highlighted with Shiki in both light and dark themes, and carry
a copy button that appears on hover.

```ts title="src/greet.ts" showLineNumbers
export function greet(name: string): string {
  return `Hello, ${name}!`
}
```

Add `title="path/to/file"` for a filename header, `showLineNumbers` for line
numbers, and braces to highlight lines:

```js {2}
const a = 1
const highlighted = 2
const c = 3
```

Highlighting runs at build time, so it adds no browser JavaScript and the
languages you never use are never downloaded. Configure it in
[Markdown options](/guide/configuration#markdown):

```ts
mdx: {
  highlight: {
    theme: { light: 'github-light', dark: 'github-dark' },
    defaultLanguage: 'plaintext',
  },
}
```

Set `highlight: false` to disable it. Code blocks, filenames and the copy button
keep working; only the token colors are dropped.

## Markdown for other tools

Every page is published twice: as HTML, and as the original Markdown at the same
URL with `.md` appended. The **Copy Markdown** button in the docs header reads
it, and the **Open** menu offers it to ChatGPT or Claude. The `llms` plugin
publishes `llms.txt` listing every page, which is a compact way to hand a whole
documentation set to a model.

<Note>
  The `.md` file is the raw source, frontmatter included, so it round-trips: you
  can paste it back into `content/` unchanged.
</Note>

## Images

Files in `public/` are copied to the output root, so `public/images/diagram.png`
is written as `/images/diagram.png`:

```mdx
![A diagram](/images/diagram.png)

<Frame caption="The dev server">
  <img src="/screenshot.svg" alt="The novon dev server" />
</Frame>
```

## Social preview images

Every page gets a `1200×630` PNG generated at build time from its title,
description and path — no server, no headless browser and no remote font. The
build writes it to `_og/<route>.png` and points `og:image` and
`twitter:image` at it.

A page's `image` or `ogImage` frontmatter, or `theme.ogImage`, takes precedence
and is used verbatim. Set `theme.generateOgImages: false` to stop generating
cards site-wide. See [Social images](/guide/configuration#social-images) for the
trade-offs, including scripts the bundled font does not cover.

## Blog posts

In a `blog` layer, non-index pages below the layer root are posts. Posts sort
newest first by `date`; the layer's generated index lists only its own posts.
`sidebar: false` hides a page from post lists, tags and RSS — useful for an About
page. Docs pages are never collected as posts. See [Layout layers](/guide/layouts).
