novon is built from three replaceable layers: **styles**, **components** and
**plugins**.

## Colours

`theme.accent` switches the primary palette, `theme.radius` the corner radius:

```ts
theme: {
  accent: 'violet',
  radius: '1rem',
}
```

Each template ships its own default palette: the docs layout uses a soft grey
shell with subtle cards, the blog layout is pure black on white. Both are CSS
custom properties, so a stylesheet can override them directly:

```css title="styles/extra.css"
:root {
  --primary: oklch(0.55 0.2 250);
  --background: oklch(0.99 0.005 250);
}

[data-theme='dark'] {
  --primary: oklch(0.75 0.15 250);
}
```

```ts
theme: { css: ['./styles/extra.css'] }
```

<Note>
  Token names follow shadcn/ui: `--background`, `--foreground`, `--card`,
  `--popover`, `--primary`, `--secondary`, `--muted`, `--accent`,
  `--destructive`, `--border`, `--input`, `--ring`. Layout widths are
  `--novon-sidebar-width`, `--novon-toc-width`, `--novon-content-width` and
  `--novon-blog-width`.
</Note>

## Custom MDX components

Point `components` at a file that default-exports a React component. It becomes
available in every page without an import:

```tsx title="components/PricingTable.tsx"
export default function PricingTable({ plan }: { plan: string }) {
  return <div className="rounded-xl border p-4">{plan}</div>
}
```

```ts
components: { PricingTable: './components/PricingTable.tsx' }
```

```mdx
<PricingTable plan="Pro" />
```

Your component can import from `novon` to reuse the theme's primitives:

```tsx
import { Badge, Button, Card, CardContent, useConfig } from 'novon'

export default function Banner() {
  const config = useConfig()
  return (
    <Card>
      <CardContent>
        <Badge>{config.title}</Badge>
        <Button size="sm">Get started</Button>
      </CardContent>
    </Card>
  )
}
```

## Theme overrides

Replace any built-in part with your own implementation. The module
default-exports a component and receives the same props as the default:

```tsx title="theme/Footer.tsx"
export default function Footer() {
  return <footer className="px-4 py-8 text-sm">A custom footer.</footer>
}
```

```ts
theme: {
  override: {
    Footer: './theme/Footer.tsx',
    Sidebar: './theme/Sidebar.tsx',
  },
}
```

Available overrides:

| Name | Replaces |
| --- | --- |
| `Header` | Top bar: the docs mobile bar, or the blog's nav. |
| `Sidebar` | The docs sidebar rail. |
| `TableOfContents` | The "On this page" panel. |
| `Footer` | Footer. |
| `HomePage` | What the blog template renders at `/`. |
| `PostListPage` | The generated `/blog` index. |
| `NotFound` | The 404 page. |

## Plugins

A plugin is a plain object. It can add files after the build, rewrite each page's
HTML, or prepare something before the build starts:

```ts title="plugins/robots.ts"
import { definePlugin } from 'novon/plugin'

export default definePlugin({
  name: 'robots',

  setup({ config, root }) {
    // Runs once, before any build work.
  },

  transformHtml(html, page) {
    // Runs for every page, on the final document.
    return html.replace('</body>', '<script src="/analytics.js"></script></body>')
  },

  postBuild(ctx) {
    // Runs after all pages are written.
    ctx.write('robots.txt', `User-agent: *\nAllow: /\nSitemap: ${ctx.config.url}/sitemap.xml\n`)
    ctx.log(`wrote robots.txt for ${ctx.pages.length} pages`)
  },
})
```

```ts
import robots from './plugins/robots.ts'

plugins: ['search', 'sitemap', robots]
```

The build context gives a plugin what it needs:

| Field | Description |
| --- | --- |
| `ctx.pages` | Every rendered page: route, title, description, headings, excerpt, HTML and output path. |
| `ctx.write(file, contents)` | Write a file relative to the output directory. |
| `ctx.config` | The resolved configuration. |
| `ctx.outDir`, `ctx.base`, `ctx.root` | Output directory, base path and site root. |
| `ctx.log(message)` | Print a line in the build output. |

A plugin object can also set `enforce: 'pre'` to run before the built-in ones.
