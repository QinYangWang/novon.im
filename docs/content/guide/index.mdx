## The two templates

`template` in the config picks the shell. Both share one component kit and one
palette, so a blog and a docs site from the same project look like one product.

**`docs`** — a full-height sidebar rail (brand, search, grouped navigation with
icons, and a theme switcher in its footer), a content header with **Copy
Markdown** and **Open** actions, an "On this page" column, previous/next cards
and a "last updated" line.

**`blog`** — a narrow single column: name and role, pill navigation, a **Copy
URL** control, a section of posts written as title + description, and a
"Connect" block of arrow pills.

<AccordionGroup>
  <Accordion title="How is the sidebar ordered?">
    Top-level directories become labelled sections and nested ones become
    collapsible groups. Within a section, pages sort by frontmatter `order`, then
    by label; pages without an `order` come last. The directory names the
    section, and its `index.mdx` is listed as an ordinary page, so the two never
    show the same label twice.
  </Accordion>
  <Accordion title="Can I use plain Markdown?">
    Yes. Both `.md` and `.mdx` files are read from `content/`. Files and
    directories starting with `_` are ignored, which is handy for partials.
  </Accordion>
  <Accordion title="Do I need a package.json in my site?">
    No. A novon site is only MDX and a config file — the CLI resolves everything
    else from its own installation. See
    [Architecture](/guide/architecture) for how.
  </Accordion>
</AccordionGroup>
