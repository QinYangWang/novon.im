A blur-up image shows a tiny blurred stand-in while the real asset loads, then
develops into the photo. A slow network sees a soft surface, never an empty
box, and a failed request lands on a clear broken-image state.

The real image is decoded before it fades in, so the transition happens once,
not per scan. Reduced motion swaps states instantly. The wrapper reports
`aria-busy` while loading and keeps the box's aspect ratio at every width.

## API

| Prop | Type | Default |
| --- | --- | --- |
| `src` | `string` | required in practice |
| `alt` | `string` | required |
| `width` / `height` | `number` — intrinsic size, locks the aspect ratio | required |
| `placeholder` | `string` — tiny image or data URI | — |
| `color` | `string` — waiting surface | `muted` token |
| `blur` | `number` — placeholder blur in pixels | `14` |
| `srcSet` / `sizes` / `loading` / `fetchPriority` | native `<img>` | `loading="lazy"` |
| `onReady` / `onError` | `() => void` | — |
| `xstyle` | `StyleXStyles` | — |

A generated or hand-made thumbnail makes the best placeholder: keep it tiny and
let `blur` do the work. Alt text describes what the image means, exactly as it
would for a plain `<img>`.
