novon is built from three replaceable layers: **styles**, **components** and
**plugins**.

## Colours

The default theme is monochrome, following the Vercel/Geist scale: a black
primary in light mode, a white primary in dark, alpha borders and a blue focus
ring. `theme.radius` sets the corner radius:

```ts
theme: {
  radius: '0.5rem',
}
```

Everything else is a CSS custom property. Add a stylesheet and override the
tokens directly, in `oklch()` or any other colour space:

```css title="styles/extra.css"
:root {
  --primary: oklch(0.55 0.2 250);
  --primary-foreground: oklch(1 0 0);
  --ring: oklch(0.55 0.2 250);
  --background: oklch(0.99 0.005 250);
}

[data-theme='dark'] {
  --primary: oklch(0.75 0.15 250);
  --primary-foreground: oklch(0 0 0);
}
```

```ts
theme: { css: ['./styles/extra.css'] }
```

<Note>
  Values and derived colors follow the [HeroUI color
  model](https://heroui.com/en/docs/react/getting-started/colors); novon's token
  names stay stable as aliases over it, so overrides keep working either way.
  Token names follow shadcn/ui: `--background`, `--foreground`, `--card`,
  `--popover`, `--primary`, `--secondary`, `--muted`, `--accent`,
  `--destructive`, `--border`, `--input`, `--ring`, plus status pairs
  `--novon-success-*`, `--novon-warning-*` and `--novon-danger-*`. Layout widths
  are `--novon-sidebar-width`, `--novon-toc-width`, `--novon-content-width` and
  `--novon-column-width`. The typefaces are `--font-sans` (Geist) and
  `--font-mono` (Geist Mono), which you can override from your own stylesheet.

  StyleX components read the same variables through
  `novon/runtime/design-system/tokens.stylex.ts`, so overriding a variable here
  restyles them everywhere. See
  [StyleX and the design system](/guide/design-system).
</Note>

Your stylesheet is loaded after the theme's, so it wins on equal specificity.
Dark mode is a `data-theme="dark"` attribute on `<html>`, set before first paint
by an inline script so the stored preference never flashes.

## Custom MDX components

Point `components` at a file that default-exports a React component. It becomes
available in every page without an import:

```tsx title="components/PricingTable.tsx"
import { Badge, Card, CardContent, CardDescription, CardHeader } from 'novon'

export default function PricingTable({ plan, price }: { plan: string; price: number }) {
  return (
    <Card>
      <CardHeader>
        <Badge variant="success">{plan}</Badge>
      </CardHeader>
      <CardContent>
        <CardDescription>${price} / month</CardDescription>
      </CardContent>
    </Card>
  )
}
```

```ts
components: { PricingTable: './components/PricingTable.tsx' }
```

```mdx
<PricingTable plan="Pro" price={20} />
```

Because the component imports from `novon`, it inherits the theme's tokens
automatically — it looks right in both light and dark mode without extra work.

## Theme overrides

Replace any built-in part with your own implementation. The module
default-exports a component and receives the same props as the default:

```tsx title="theme/Header.tsx"
import * as stylex from '@stylexjs/stylex'
import { Brand, SearchTrigger, ThemeSwitch } from 'novon'
import { colors, layout, space } from 'novon/runtime/design-system/tokens.stylex.ts'

const styles = stylex.create({
  header: {
    display: 'flex',
    height: layout.header,
    alignItems: 'center',
    gap: space.four,
    borderBottomWidth: 1,
    borderBottomStyle: 'solid',
    borderBottomColor: colors.border,
    paddingInline: space.four,
  },
  actions: { marginInlineStart: 'auto', display: 'flex', alignItems: 'center', gap: space.two },
})

export default function Header() {
  return (
    <header {...stylex.props(styles.header)}>
      <Brand />
      <div {...stylex.props(styles.actions)}>
        <SearchTrigger />
        <ThemeSwitch />
      </div>
    </header>
  )
}
```

```ts
theme: {
  override: {
    Header: './theme/Header.tsx',
    Footer: './theme/Footer.tsx',
  },
}
```

| Name | Replaces |
| --- | --- |
| `Header` | Top bar: the docs mobile bar, or the blog's nav. |
| `Sidebar` | The docs sidebar rail. |
| `TableOfContents` | The "On this page" panel. |
| `Footer` | Footer. |
| `DocsHeader`, `BlogHeader` | Layout-specific header; takes precedence over `Header`. |
| `DocsFooter`, `BlogFooter` | Layout-specific footer; takes precedence over `Footer`. |
| `HomePage` | A blog layer's generated home page. |
| `PostListPage` | The extra `/blog` index of a root blog. |
| `NotFound` | The 404 page. |

## Plugins

A plugin is a plain object. It can add files after the build, rewrite each page's
HTML, or prepare something before the build starts:

```ts title="plugins/robots.ts"
import { definePlugin } from 'novon/plugin'

export default definePlugin({
  name: 'robots',

  setup({ config, root }) {
    // Runs once, before any build work.
  },

  transformHtml(html, page) {
    // Runs for every page, on the final document.
    return html.replace('</body>', '<script src="/analytics.js"></script></body>')
  },

  postBuild(ctx) {
    // Runs after all pages are written.
    ctx.write('robots.txt', `User-agent: *\nAllow: /\nSitemap: ${ctx.config.url}/sitemap.xml\n`)
    ctx.log(`wrote robots.txt for ${ctx.pages.length} pages`)
  },
})
```

```ts
import robots from './plugins/robots.ts'

plugins: ['search', 'sitemap', robots]
```

| Hook | When | Receives |
| --- | --- | --- |
| `setup` | Once, before the build | `{ root, config, outDir, base, packageRoot }` |
| `transformHtml` | Every page, on the final document | `(html, page, ctx)` |
| `postBuild` | After all pages are written | `ctx` with `pages` and `write()` |

The build context gives a plugin what it needs:

| Field | Description |
| --- | --- |
| `ctx.pages` | Every rendered page: route, title, description, headings, excerpt, HTML and output path. |
| `ctx.write(file, contents)` | Write a file relative to the output directory. |
| `ctx.config` | The resolved configuration. |
| `ctx.outDir`, `ctx.base`, `ctx.root` | Output directory, base path and site root. |
| `ctx.log(message)` | Print a line in the build output. |

Set `enforce: 'pre'` to run before the built-in plugins, or `'post'` to run after.

<Note>
  Plugin files imported from `novon.config.ts` are loaded the same way the config
  is: their `novon/...` imports are resolved against the installed package, so a
  plugin needs no `node_modules` of its own.
</Note>
